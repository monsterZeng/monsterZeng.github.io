DuplexJev：不解码的批量语音决策 —— 论文总结¶

原文：Batched Speech Decisions Without Decoding: Single-Token Supervision Lets a Frozen LLM Hear Beyond the Transcript（arXiv:2610.02638v1，cs.AI，2026-10-02，投稿 ICASSP 2027，5 页）
快捷入口：摘要页 ｜ PDF ｜ HTML 全文
作者：Jie Jin、Ziyin Ma、Yin Min、Jinyu Chen、Haigang Song、Zhikun Pang、Xiaowen Zhang
机构：Adventists.ai（墨尔本）、浙江大学计算机学院、浙大长三角智慧绿洲创新中心、弗吉尼亚大学
开源：代码 GitHub（pip install duplexjev）｜ DuplexJev-4B 权重 ｜ DuplexJev-4B-Para ｜ DuplexJev-32B ｜ qa100 数据集 ｜ 在线试用

一、一句话概括¶

冻结的 ASR 编码器加冻结的 LLM，中间只训练一个约 2000 万参数的连接器。每个封闭式问题把选项写成字母，只看答案位置的下一个 token 在这些字母上的概率，一次前向就得到决策，不做任何解码。另一个核心发现是：常规的“转写蒸馏”训练会让语音 LLM 听不出说话人，必须直接监督被读出的那个答案 token。

二、要解决的问题（§1）¶

  • 全双工语音助手边听边说，每轮都要回答一堆小的封闭问题：这一轮说完了吗？是附和（backchannel）还是打断（barge-in）？该放哪段预录的语气词？谁在说话？作者把这类任务叫 speech-to-decision，和 speech-to-text 区分开。
  • 真实成本：在一款已上线的车载助手里，这类决策靠生成文本完成，占了全部 LLM 输入 token 的 30%。而且它们挡在回复前面，每一轮都要等它们算完才能开口。
  • 现有方案的问题：
  • 端到端全双工模型（如 Moshi）每一帧都要解码，每通电话占一条解码流，批量服务昂贵，决策也不以类型化输出暴露出来；
  • 级联方案先转写再生成，慢，而且丢掉了声音里的信息；
  • 专用的轮次分类器（如 Easy-Turn）便宜，但一个模型只能回答一个固定问题。
  • 动机来自 TypeSafe 的 “System-One” 决策模型 Jev 和社区项目 OpenJev：给定状态和运行时声明的问题，直接返回选项分布，不生成文本。

三、方法（§2，架构见 Figure 1）¶

3.1 连接器（§2.1）¶

编码器（论文里用 Qwen3-ASR-0.6B）和 LLM 全部冻结，只训练连接器。对比了两种设计：

变体 结构 可训练参数
B：只用最后一层 编码器第 18 层（最后一层）→ Ultravox 式投影器（帧堆叠 + MLP）→ LLM 嵌入空间 17.8M
A：交叉注意力融合 投影器之前加融合块：Q 来自第 18 层、K 来自第 14 层、V 来自第 9 层；输出投影零初始化、以残差加到最后一层，所以训练起点和 B 完全一样 21.1M（融合 3.2M + 投影 17.8M）

设计 A 是为了检验一个常见直觉：ASR 微调让最后一层偏向语言内容，中间层保留说话人和韵律信息。作者的探针实验不支持这个直觉（见下文 5.3）。

3.2 训练目标：转写蒸馏 vs. 答案 token 监督（§2.1）¶

  • 转写蒸馏（用于内容理解）：让冻结 LLM 在“听音频嵌入”时的输出分布，去匹配它在“读标准转写文本”时的分布（token 级 KL，温度 2）。这是 Ultravox、DiVA 等的常规做法。
  • 问题在于老师听不到声音：对于答案不在文字里的问题（性别、情绪），老师给出的只是纯文本先验，学生被训练得和老师一样“一无所知”。
  • 答案 token 监督：只对被读出的那个答案字母做交叉熵，位置和模板与推理时完全一致；前面固定的对话模板 token（比如空的思考块）不计入损失，所以字母是唯一被监督的 token。
  • 混合目标（MIX-KD）：每个样本保留各自的损失，内容类样本（转写、续写）用蒸馏，决策类样本用答案 token 交叉熵，两部分平均后相加。

3.3 类型化单 token 读出（§2.2）¶

这就是它的“决策头”，没有新增任何层，直接复用 LLM 自身的词表输出：

  • 一个请求包含状态 S_t（截至 t 时刻的音频，可附加智能体状态）和 N 个类型化问题。
  • choice：K 个选项列在字母 A、B、…… 下面，字母顺序随机打乱以消除位置偏差。
  • boolean：用 N / Y 两个 token。
  • score：用 1..K 这些数字 token。
  • 一次前向，取答案位置的 logits，只保留这 K 个选项 token 再重新 softmax，就是选项分布。
  • 不采样，所以输出永远合法；最大概率可以直接当置信度，用于拒答。

3.4 批处理与成本（§2.3）¶

  • 每个问题只需一步，同一状态或不同通话的问题都可以放在一起算。
  • 朴素做法（batch-repeat）：每行复制整段 prompt，每行都重新编码一遍音频和对话上下文。
  • 前缀共享：N 个问题的最长公共前缀（模板、对话上下文、音频，长度 P）只编码一次进 KV 缓存；N 个问题后缀拼进同一行，用块对角的 4-D 注意力掩码让每个后缀只看前缀和自己，位置编号对每个后缀都从 P 重新开始。
  • 计算量 ≈ C(P) + Σ C(L_j)，而不是 N·C(P + L̄)；
  • KV 缓存只占 P + Σ L_j 个位置，而不是 N·(P + L̄)，长共享上下文不会让显存成倍增长。
  • 对比：全双工模型不论是否需要决策，每通电话的每一帧都要解码一步；级联方案每个决策要 O(转写 + 答案) 步自回归。

3.5 部署模式（§2.4）¶

  • 因为一次只需一步，可以按固定时钟运行：每个 tick（如 160–200 ms）收集所有在线通话的最新音频，一次批处理回答全部决策集合。
  • 轮次判断（说完、附和、打断）可以作为其中一个问题，有望替代独立的 VAD 或端点检测器。但论文没有评测流式输入。
  • 业务决策（语气词、路由、历史）共用同一次前向。例如语气词：线上系统为生成一个 20 token 的语气词要发一次 5k token 的 LLM 调用；改成从大的预录库里选一个，用布尔行筛候选清单，或者用一棵逐级的字母选择树，库扩容不用重新训练。

四、实验设置（§3）¶

  • 模型：论文实验的 LLM 是 Qwen3-32B（冻结，bf16，嵌入维度 5120）；编码器是 Qwen3-ASR-0.6B（冻结）。A 用 8×H200 训练，B 用 8×A800；全局 batch 16，学习率 2e-4，每轮 32k 步。
  • 训练轮次：
  • R1–R2：只做内容任务（转写、续写），用蒸馏；数据是 WenetSpeech、GigaSpeech、LibriSpeech、Common Voice、CoVoST 的混合，切成 100 个互不重叠的包，R1、R2 各用 1 个（每轮 50 万条）。
  • R3：副语言阶段，从 R2 连接器出发。性别包 3.2 万条真实语音（AISHELL-1、LibriSpeech）；情绪包 2.6 万条四分类（中性、开心、生气、难过），来自 ESD 和 CREMA-D。每个片段三种任务各占三分之一：转写、续写、一道打乱字母和改写题干的封闭题。测试说话人与训练完全不重叠，不用合成语音。
  • 评测集：
  • qa100（本文发布）：100 道四选一，中英各 50，逻辑题和事实题各半；题干用 VoxCPM2 合成，选项以文本给出。三种条件：听音频、读标准转写（上界）、只看选项（下界 36%）。
  • ZJU-ML：ZJU 音频基准 v2.0.0 的主语言部分，100 道四选一，一半真实录音、一半合成。
  • Easy-Turn：零样本四分类轮次状态。
  • 性别：自建 800 条真实语音，加 ZJU 性别基准 v1.2.0（100 条，一半真实一半合成）。情绪：800 条，四类均衡，取自 ESD 留出说话人和 CREMA-D 演员。两个情绪语料都是同一句话用不同情绪朗读，所以只读文字必然是随机水平。
  • 线上负载：DoumaoAI 运营的车载助手 Dimi（Qwen3-ASR-0.6B → 72B LLM → TTS），91 天内 3721 台设备、145 万轮用户对话。每轮最多三次 LLM 调用只为做小决策：要不要调工具（输入中位数 1471 token）、意图标签（530）、20 token 的开场语气词（5020）。从用户说完到第一个音频输出的中位延迟 1.29 秒。
  • 成本测试：单张 H200，bf16。级联基线每个事件回答 10 个问题（8 选 1 的语气词、6 选 1 的路由、1–5 的紧急度、是否说完等）：ASR 贪心转写，再由 vLLM 上的 Qwen3-32B 生成一个 10 字段的 JSON。

五、主要结果（§4）¶

5.1 延迟与容量（Table 1，单张 H200，Qwen3-32B on vLLM）¶

上下文 方式 解码步数 单事件延迟 (ms) 0.25 s 内事件/秒 0.5 s 内 2 s 内
0 JSON 生成 86 1567 0 0 16.9
0 单 token 读出 0 92 17.3 20.4 33.5
1.5k JSON 生成 87 1598 0 0 8.4
1.5k 单 token 读出 0 144 9.7 12.0 18.4
  • 同一引擎下，10 个决策用单 token 读出 92 ms，生成 JSON 要 1.57 s，快 17 倍，而且还没算级联方案额外的 411 ms 转写。带 1471 token 对话上下文时快 11 倍。
  • 0.5 秒预算内，JSON 方案一个事件都服务不了，读出方案单卡能服务 17–20 个事件/秒。
  • 8×H200 节点（每卡一个引擎）：8 个事件共 80 个决策在 94–103 ms 内完成；0.5 秒预算内服务 161 事件/秒（1613 决策/秒），饱和时 3684 决策/秒。
  • 作者自己承认的局限：完全饱和时（64 个并发事件）两者吞吐打平（335 vs. 311 决策/秒），因为批量解码本身便宜，而且一个 JSON prompt 能把对话上下文摊到 10 个问题上，读出方案却在每个问题行里重复转写和指令。优势在对话时延预算下的延迟和容量，不在原始吞吐。
  • 前缀共享是精确的：共享和逐个读出在 200 个问题–语句对上，答案一致的有 195（A）和 198（B）个；在 0.5k–5k 上下文下 40/40 一致；差异几乎都是近似平局，属于 bf16 数值噪声。
  • 前缀共享消除上下文成本：batch-repeat 在 5k 上下文下 5 个问题就爆显存；打包成一行后，1.5k 上下文 100 个问题 5.1 秒（逐个 37.9 秒），5k 上下文 50 个问题 5.5 秒（逐个 112 秒）。
  • 批处理不改变答案：800 条性别测试中 790 条一致，ZJU 上 99–100/100 一致。

  • 蒸馏教不会文字里没有的东西：蒸馏 6k 步后性别仍是随机水平（53%），答案保留文本先验（女性召回 0.3，男性 0.8）。换数据配比、学习率提高 5 倍、从随机连接器重训、甚至在训练集上用训练 prompt 测（56%），都还是随机水平，而损失一直在下降——学生在完美地模仿一个“听不见”的老师。
  • 只换损失就能学会：同样的数据和步数，答案 token 监督让性别到 89%（A）/ 88%（B），情绪到 72%（A）/ 86%（B）。性别题占 80% 时，250 步就学会（A：92%，ZJU 原生 97%）。
  • 交叉检查说明学到的是声学线索而不是答案偏置：只训性别的模型在情绪上仍是随机水平，只训情绪的模型也不知道性别。
  • 瓶颈在目标函数，不在连接器：线性探针显示，性别（97–99%）和情绪（88–93%）在编码器最后一层和连接器输出里本来就线性可分。A 和 B 学性别的速度相同，情绪上 B 甚至更好。这也否定了“中间层才有说话人信息”的直觉。
  • 内容理解的代价：qa100 上所有答案监督的结果都在起点 ±3 分以内（MIX-CE 是 −4）。但 ZJU-ML 掉得很明显：情绪数据掉 6–10 分，两种四任务混合掉 16–17 分，几乎全掉在真实录音的事实题那一半。混合目标没有缓解这个漂移，但保住了 qa100（−1 vs. −4），并给出最好的副语言成绩。

六、结论（§5）¶

一次冻结 LLM 的前向就能从语音读出多个类型化决策。转写蒸馏出来的语音 LLM “听不见说话人”，是因为老师听不到声音；直接监督被读出的 token，LLM 就能用上编码器里本来就有的性别和情绪线索。下一步是在端侧用小 LLM 做门控决策。

七、阅读时发现的问题（建议核对）¶

  1. 摘要回避了一个明显的代价：摘要说交叉注意力连接器做到性别和情绪 90%，“口语问答只掉 1 分（83→82）”，这指的是 qa100。但同一组设置（A, MIX-KD）在 ZJU-ML 上掉了 16 分，而且主要掉在真实录音的事实题上。真实录音才更接近线上场景，这个数字在摘要里没有出现。
  2. “0.1 秒回答 80 个决策”要看清楚条件：这是 8 张卡各跑一个引擎、各处理 1 个事件，等于单卡 1 个事件约 92 ms。而且 Table 1 的 vLLM 计时用的是转写文本代替音频嵌入，不是真正的端到端音频输入。作者说明这会略微低估实际成本，因为音频 token 比转写多 10–33 个。PyTorch 计时和前缀共享实验用的又是更早的连接器（堆叠因子 8，约 1.6 token/秒），和最终连接器（6.25 token/秒）不同。
  3. 饱和吞吐没有优势：作者自己承认，满载时与 JSON 方案打平。真正的卖点是“对话时延预算下的延迟和容量”。
  4. 没有校准训练：用 max p 当置信度并做了拒答实验，但没有 ECE 之类的校准指标，也没有类似 Qwen-Audio-Jev 中 RLCD 的校准阶段。
  5. 流式没有评测：固定时钟、替代 VAD 的部署模式只是提议，作者明确说“we do not evaluate streaming input here”。
  6. 论文模型与发布模型不一致：论文实验全部基于 Qwen3-32B，连接器 17.8M/21.1M；而 DuplexJev-4B 模型卡说它是“paper model”，用的是 Qwen3-4B，连接器 12.6M，评测协议和数字也和论文表格不同。复现论文结果应该看 DuplexJev-32B，但这一点需要到 GitHub 上确认。
  7. 评测集偏小：qa100、ZJU-ML、ZJU 性别都只有 100 题，1 题就是 1 个百分点，几分的差异未必显著；情绪数据来自表演语料。

八、对你研究的启发（个人解读，非原文内容）¶

结合你在看的 Moshi 式全双工 + 实时工具调用，以及对上下文膨胀的担心：

  • 把决策从主生成流里拆出来：Moshi 每通电话每帧都要解码一步，所有判断都混在同一条流里。DuplexJev 的思路是让主模型只负责“说”，轮次、打断、要不要调工具、调哪个工具这些判断，按固定 tick 交给一个旁路决策器批量处理。这本身就是一种“想”和“说”的解耦。
  • 前缀共享直接回应上下文膨胀：块对角掩码 + 共享前缀 KV，让 N 个问题共享一份长对话上下文，KV 只占 P + Σ L_j。如果你的系统需要在同一段长上下文上频繁做多个判断，这个技巧可以直接借鉴，也可以用 vLLM 的前缀缓存近似实现。
  • 工具调用门控是现成的应用：线上系统里“要不要调工具”的检查，输入中位数 1471 token，每轮都要跑。把它做成一个 boolean 读出，就是一次前向的事；工具选择可以做成 choice，参数抽取仍交给主模型。
  • “不生成，而是选择”：语气词从预录库里选，而不是现场生成，这个思路可以推广到全双工里的 backchannel、过渡语、等待提示音。
  • 训练上的警示：如果你的全双工模型主要靠文本老师蒸馏，它很可能“听不见”语气、情绪和打断意图。凡是答案不在文字里的判断，都需要直接用声学标签监督。
  • 局限同样相关：只在短句、朗读语音上测过，没有在流式部分音频上验证，“wait” 类轮次召回只有 0.3。真正用于全双工的端点检测前，还需要你自己在流式数据上测。

九、与 Qwen-Audio-Jev 的对比¶

维度 DuplexJev Qwen-Audio-Jev
场景 全双工对话中的轮次、语气词、副语言、业务决策 通用音频决策：分类、验证、质量打分
训练范围 编码器和 LLM 冻结，只训 ~2000 万参数连接器 全参数微调
决策头 无新层，复用 LLM 词表输出，只取选项字母 / Y-N / 数字 token 再 softmax 新增三个线性投影（64 / 1 / 10 维），接在前缀最后一个 token 的隐藏状态上
选项顺序 字母顺序随机打乱 训练时随机打乱候选
校准 无专门校准训练，max p 用于拒答 SFT 后再加 RLCD（Brier / RPS 奖励）
批处理 前缀共享 + 块对角掩码，多问题打包一行 每个问题单独一次前向
开源 权重、代码、训练配方、qa100 未开源
