Moshi-Face：给全双工语音对话模型加上 3D 人脸 —— 论文总结¶

原文：Integrating Facial Generation into Full-Duplex Spoken Dialogue Systems（arXiv:2606.21970v1，cs.HC，2026-06-20，Interspeech 2026 已接收） 快捷入口：摘要页 ｜ PDF ｜ HTML 全文 ｜ Emergent Mind 页面（该站把标题写成了 “Moshi-Face: Real-Time Facial Generation in Dialogue”，与 arXiv 正式标题不同） 作者：Jingjing Jiang、Atsumoto Ohashi、Ryuichiro Higashinaka 机构：名古屋大学 情报学研究科（东中竜一郎组；同组之前做过日语版 Moshi：J-Moshi） 开源：论文未给代码或权重链接；只引用了所用的 Moshi 预训练权重 moshiko-pytorch-bf16

一、一句话概括¶

在 Moshi 的“文本 + 双方音频”多流结构上，再加双方的人脸 token 流：先用 VQ-VAE 把 3D 人脸网格（FLAME 拓扑）压成 12.5 Hz、每帧 8 个离散 token 的“face token”，再在 7B 主干后面挂一个小的非自回归 Face Transformer，每个时间步一次性并行输出 8 个 face token。这样模型能同时“听+看”用户、同时“说+做表情/口型/头动”。作者称这是第一个能同时处理和生成语音与人脸的全双工对话模型。

二、要解决的问题（§1）¶

已有路线 代表 不足
能理解或生成人脸的多模态对话系统 Let's Go Real Talk（ACL 2024）、UniTalker（ACM MM 2025）、Seeing is Believing（EMNLP 2025 Findings） 都是轮次式，同一时刻只能一方说话，没有重叠、附和（backchannel）
全双工语音对话模型 Moshi、Freeze-Omni、dGSLM、J-Moshi 只有音频，不处理也不生成口型、表情、头部动作

目标是把两者合起来：全双工 + 音视频双向。

三、方法（§2，总览见 Figure 2）¶

3.1 Face Codec：把人脸变成 token（§2.1）¶

  • 结构沿用 CodeTalker 的 VQ-VAE：编码器是“1-D 下采样卷积 + 一层 Transformer”，解码器与之对称。
  • 输入：每帧是 FLAME 网格的 5,143 个顶点相对于中性脸的位移，25 fps。
  • 时间下采样 r=2，所以 25 fps 变成 12.5 Hz，正好和 Moshi 的 Mimi 音频 token 对齐。
  • 每帧编码成 N=8 个向量，各自独立地查最近的码本条目，得到 8 个 face token。最终配置：码本大小 K=256，维度 C=128（Table 1）。
  • 损失 = L1 重建 + 量化损失 + 速度损失（相邻帧差分）。

3.2 输入输出流（§2.2）¶

每个 12.5 Hz 时间步：

流 输入 输出 来源
文本（Inner Monologue） 1 1 Moshi 原有
音频 2M = 16（系统 8 + 用户 8） M = 8 Mimi codec
人脸 2N = 16（系统 8 + 用户 8） N = 8 新的 Face codec

音频和人脸流都相对文本延迟 1 步，沿用 Moshi 的做法以提高稳定性。

3.3 模型结构（§2.3）¶

  • RQ-Transformer（Moshi 原样）：7B Temporal Transformer + 小 Depth Transformer，自回归地产生隐状态 h、文本 token 和音频 token。输入包含历史的文本、音频和人脸 token（式 (1)）。
  • Face Transformer（新增）：
  • 把隐状态 h、当前文本 token 的 embedding、8 个音频 token 的 embedding 相加，得到条件向量 e^All（式 (2)）；
  • 投影后加上 N 个可学习位置编码，得到 N 个 query；
  • 在这 N 个位置之间做非因果自注意力，再用 N 个线性头并行预测 8 个 face token（式 (3)）。
  • 能并行的理由：VQ 是对 8 个向量各自独立量化的，不像音频 RVQ 那样有逐层残差依赖，所以不需要像 Depth Transformer 那样一层一层地生成。
  • 训练时还把上一步（i−1）的真实 face token embedding 加到 query 上（teacher forcing），让人脸在时间上保持连续（§3.2）。
  • 总损失：L = L_text + L_audio + λ·L_face，λ=1。

四、数据与训练（§3.1、§3.2）¶

数据：常用的 3D 说话人脸数据集（VOCASET、BIWI）都只有几分钟、而且不是对话。作者从 Meta 的 Seamless Interaction 数据集里随机下载约 180 小时、约 3,400 段面对面对话（双声道音频 + 双方单人视频 + 对齐转写），再用 VHAP（论文引用的是 GaussianAvatars）从单目视频中提取 25 fps 的 FLAME 网格。

两阶段训练：

阶段 内容 数据 超参
阶段 1：Face codec 训练 VQ-VAE 70 小时网格，8:1:1 划分 70 epoch，AdamW，lr 1e-4，batch 4
阶段 2 / Step 1 冻结 RQ-Transformer，只训 Face Transformer 3,300 段对话，9:1 划分（另留 100 段测试） lr 5e-4，500 步，batch 32
阶段 2 / Step 2 全部联合微调 同上 lr 2e-6 / 4e-6 / 1e-5（Temporal / Depth / Face），1,200 步，batch 16

RQ-Transformer 由 moshiko 权重初始化。训练量很小，总共不到 2,000 步。

五、实验结果¶

5.1 Face codec（§3.3，Table 1）¶

K（码本大小） C（维度） 归一化困惑度 ↑ MVE ↓（×10⁻³） LVE ↓（×10⁻³）

码本从 128 增大到 256 时，误差下降；C=128 的码本利用率更均匀。最终选 K=256、C=128。

5.2 Moshi-Face 主结果（§3.4，Table 2）¶

两种评测设置：

  • Teacher-forced：喂入 100 段测试对话的真实音频 token，只考察人脸生成；
  • Free-run：两个 Moshi-Face 互相对话（一方的输出作为另一方的输入），模拟真实的全双工场景。

评测指标：

  • 口型同步：渲染成 2D 视频后，用 SyncNet 计算 LSE-D 和 LSE-C（做法沿用 Wav2Lip）；
  • 语音自然度：UTMOS；
  • 语义质量：先用 Whisper-large-v3 转写，再由 GPT-5-mini 按 LLM-as-a-Judge 打 1–5 分，每个样本评三次取平均。

Moshi-ft（只用音频微调） – – – – 1.69 3.59 4.28 3.95 3.55

（TF = teacher-forced，FR = free-run。“–” 表示该项不适用或论文未报告。）

作者的结论：

  1. Teacher-forced 下 LSE-D 为 8.76，接近上界 8.53，明显好于随机的 11.7。
  2. Free-run 下仍然“保持了可比的同步质量”。
  3. UTMOS 下降，是因为在 180 小时的小规模领域数据上微调损害了 Moshi 的音质；Moshi-ft 同样从 3.08 降到 1.69，可以佐证这一点。
  4. LLMAJ 的连贯度最高，自然度第二，总体分与 Moshi 相当。作者据此认为加入人脸没有损害对话质量，甚至可能提供了有益的多模态上下文。

消融：

  • 去掉 Step 1，teacher-forced LSE-D 从 8.76 变差到 9.53；
  • 去掉 Step 2，同步和 LLMAJ 都最差（只训一个小头、主干冻结是不够的）；
  • 去掉 t−1 输入，free-run LSE-D 反而变好（10.1），但 LSE-C 和 UTMOS 下降。作者解释为“抗误差累积”与“生成质量”之间的权衡。

六、结论与未来工作（§4）¶

作者明确承认：当前的 face codec 是非因果的，下一步要换成因果的流式 codec，才能做到真正实时的视觉输入和输出。另外还要补做人工主观评测。

七、存疑与不一致之处¶

  1. “实时、低延迟”只是结构上可行，并没有测出来。 摘要说 “achieves audiovisual alignment at low latency”，但全文没有报告任何延迟或实时率数据。而且结论里自己承认 face codec 是非因果的（编码器含 Transformer 层，需要看到未来帧），所以目前的“实时”只是说 face token 与音频 token 帧率相同、每步一次前向就能生成，并不等于端到端系统真的能实时跑通。

  2. LSE-C 基本没有区分度。 上界 Reconstructed 为 0.12，随机人脸反而是 0.13，Moshi-Face 为 0.14。上界比随机还低，说明这个指标在“3D 网格渲染成视频”的场景下基本失效。常见的真实视频 LSE-C 在数个点的量级，我推测原因是 SyncNet 训练用的是真人视频，与无纹理的渲染网格存在域差异；论文没有讨论这一点。因此，同步结论实际上只靠 LSE-D 一个指标支撑。

  3. Free-run 的同步“可比”说得偏宽。 Free-run 下 LSE-D 为 11.0，随机下界是 11.8，两者只差 0.8；而 teacher-forced 下与上界的差距是 0.23，与随机的差距约 3。free-run 没有上界可以对照，“comparable synchronization quality” 这一说法证据不足。另外，“去掉 t−1 输入”的 free-run LSE-D（10.1）比完整模型更好，这暗示 teacher forcing 带来了暴露偏差（exposure bias）：训练时用真值，推理时用自己的输出，误差会逐步累积。

  4. “保持对话质量”只在 LLMAJ 维度上成立。 UTMOS 从 3.08 跌到 1.75，降幅很大；总体分是 3.76，原版 Moshi 是 3.85。作者用 Moshi-ft 同样下跌来归因于数据，这个论证合理，但摘要里 “preserving the dialogue quality” 的表述没有提到音质的大幅下降。

  5. 公式与训练描述对不上。 式 (2) 的条件向量只包含 h、文本和音频 embedding；但 §3.2 又说上一步的 face token 也被加到 query 上。另外，式 (1) 写明 RQ-Transformer 也读入历史 face token，可是论文没有交代 16 路人脸流是如何进入 7B 主干的（按 Moshi 的惯例应是 embedding 相加，但文中没写）。因此，消融里的“w/o t−1 face token input”到底去掉的是 Face Transformer 的 query 输入、还是主干的输入，也不清楚。

  6. 用户人脸输入的作用没有被单独验证。 摘要强调模型能 “jointly processes the user's audio and facial input”，但没有任何实验去掉用户人脸流来检验它是否真的被利用了（例如是否会根据用户表情做出反应）。

  7. Teacher-forced 的“去掉 Step 2”（11.8）比随机人脸（11.7）还差。 这说明在冻结主干上只训练 Face Transformer 几乎学不到口型对应关系。这本身是个有价值的发现，但作者只写成“最差”，没有进一步分析。

  8. 小问题：

  9. VHAP 本是独立的工具，论文引用的却是 GaussianAvatars；

  10. Emergent Mind 页面的标题与 arXiv 不一致；
  11. Emergent Mind 的摘要说“去掉 t−1 改善了 LSE-D”，其实只在 free-run 下改善，teacher-forced 下是从 8.76 变差到 11.3。

八、与对话交互研究的关系¶

1. 对“上下文爆炸”担忧的启示：在 Moshi 式结构里加模态，主要增加的是每步的宽度，而不是序列长度。 在 Moshi 中，每个 80 ms 时间步把 17 个 token（1 文本 + 双方各 8 个音频）的 embedding 相加成一个位置（参见本库对比笔记）。Moshi-Face 又加了 16 路人脸流，如果沿用相加的做法，Temporal Transformer 的序列仍然是每秒 12.5 个位置，3000 步的窗口仍然约等于 4 分钟。新增的开销落在：

  • 每步的 embedding 查表；
  • 一个额外的小 Face Transformer。

这说明按时间对齐、多流相加的设计对多模态扩展相当友好；真正限制时长的仍然是时间轴本身。反过来，如果改用时分交错的单序列方案（如 SyncLLM、OmniFlatten 一类），加一路视频就会直接拉长序列。

2. “挂在主干隐状态上的并行小头”可以迁移到工具调用。 Face Transformer 的模式是：读取主干每步的 h 和当前文本/音频，用一次非自回归前向输出一组结构化 token，不占用主干的自回归步数。同样的结构可以用来做：

  • 每步一个“是否触发工具 / 触发哪个工具”的分类头；
  • 异步工具结果的状态通道。

本文的消融也提醒我们，只训小头、冻结主干是行不通的（同步分数甚至比随机还差）；主干必须联合微调才能把相关信息写进 h。这一点与 Freeze-Omni 冻结 LLM 的思路形成对照。

3. 并行与自回归的选择取决于 token 之间有没有依赖。 音频 RVQ 存在层间残差依赖，所以需要 Depth Transformer 逐层生成；人脸 VQ 的 8 个分量是独立量化的，所以可以并行。为工具调用或其他结构化输出设计 codec 时，可以有意把各分量设计成独立的，从而换取一步出结果的低延迟。

4. 评测方法值得借用。

  • “两个模型互相对话”的 free-run 自博弈，可以低成本评测全双工系统；
  • 本文也暴露了这种做法的问题：同步指标退化到接近随机水平，说明长时间自回归下的误差累积是全双工多流模型的共性风险。工具调用流如果也是自回归生成，同样需要在 free-run 下单独评估，不能只看 teacher-forced 的结果。

5. 局限：数据量小（180 小时）、只有英文 Seamless 数据、没有人工评测、没有开源。可以把它当作“架构可行性”的证据，还不能当作可直接复用的系统。
