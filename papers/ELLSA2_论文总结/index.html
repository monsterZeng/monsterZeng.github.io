ELLSA 2：语音、手势、表情一体的全双工对话模型 —— 论文总结¶

名字：ELLSA = Expressive LLM that Listens, Speaks, and Acts。上一代 ELLSA（End-to-end listen, look, speak and act，ICLR 2026）做的是视觉感知和机械臂操作，这一代转向手势和表情。

一、一句话概括¶

在 SALMONN-omni 全双工语音对话模型上，外挂一个 0.5B 的自回归手势-表情生成器。它每 0.8 秒读一次“我在说的话”（来自语音合成器的隐状态）和“对方在说的话”（来自 LLM 主干的隐状态），输出上半身、双手、面部、嘴部共 18 路 RVQ 码。模型不说话时也一直在生成，所以能做点头、微笑这类倾听反应。另外，主干上挂了一个语义调用头，判断“此刻要不要做一个有明确含义的手势”（比如说“房子很大”时张开双手）；一旦判定要做，就从 3,227 条模板库里取一条示范动作，插进生成序列做引导。语音能力基本保持 SALMONN-omni 的水平，手势和表情指标超过级联基线，模板引导把人工语义分从 2.014 提到 2.711。

二、要解决的问题（§1、§2）¶

人面对面交流时，说话人会用手比划大小，听话人会点头、挑眉，这些行为本身就承载意义，也在组织对话节奏。作者的观点是：非语言行为应当是对话过程的一部分，而不是语音生成完之后再贴上去的动画。

现有工作分属两条线，作者认为都不够：

路线 代表 不足
全双工语音模型 双模型“监听-生成”式的 VITA-1.5、Freeze-Omni；连续生成式的 Moshi、PersonaPlex；显式对话状态预测的 SALMONN-omni 只输出语音
语音驱动手势/表情 自回归的 BEAT、EMAGE；扩散的 DiffSHEG；流匹配的 GestureLSM；双人对话的 DiffuGesture、Seamless Interaction、DyaDiT；表情方向的 DualTalk、UniLS、FacePlex 输入是“已经给定的语音”，不参与对话决策；语义手势（有明确含义的手势）很难学
两者结合的早期尝试 ViBES（多任务分开支持）、MIBURI 和 DyaPlex（基于冻结的语音交互模型表征生成手势） 没有联合优化

ELLSA 2 的定位是：第一个把语音、手势、表情端到端联合优化的全双工对话模型。作者强调，真正的问题不在于多加几种输出模态，而在于怎样让对话理解来协调这些模态：倾听反应需要理解对方说的内容；语义手势需要判断某个动作是否适合当前要说的话。

3.1 流式、对话感知的手势-表情生成器（§3.1，附录 A.1–A.2）¶

“对话感知”指生成时同时看模型自己的语音和对方的语音；“流式”指可以在线逐块生成，满足实时交互的延迟要求。两者都通过“按块交错的自回归语言建模”实现：

  • 块长 0.8 s。每块内的序列顺序是：说话音频 → 倾听音频 → 手势/表情 token。因果注意力天然支持流式推理。
  • 动作表示：身体用 SMPL-H，脸用 FLAME。目标拆成上半身、双手、面部三部分，各自用一个区域专用的 RVQ-VAE（残差向量量化，参见 Lee et al. 2022）编码。下半身不建模，因为视频里经常看不到，监督不可靠（沿用 DyaDiT 的观察）。
  • 帧率对齐：动作原始 30 Hz，RVQ-VAE 编码器下采样 4 倍到 7.5 Hz；语音表征是 12.5 Hz。

每个 0.8 s 块的 token 预算如下：

内容 每块数量 说明
说话语音 embedding 10 12.5 Hz × 0.8 s
倾听语音 embedding 10 同上
动作潜变量步 6 7.5 Hz × 0.8 s，对应 24 帧原始动作
每个潜变量步的码本索引 18 上半身 6 + 双手 6 + 非嘴部表情 4 + 嘴部表情 2

18 路码本不是逐层自回归生成的（这点和 Moshi 的 Depth Transformer 不同）。18 路码本的 embedding 加权求和后作为一个时间位置输入，再由 18 个独立的分类头从同一个隐状态并行预测。块内的生成概率是（式 (3)）：

\[ p(z_k \mid z_{<k}, c_{\le k}) = \prod_{j=1}^{6} \prod_{q=1}^{18} p_\theta\!\left(z_{k,j}^{(q)} \mid z_{<k},\, z_{k,<j},\, c_{\le k}\right) \]

其中 \(k\) 是第 \(k\) 个 0.8 s 区间 \(I_k=[k\Delta,(k+1)\Delta)\)，\(\Delta=0.8\) s；\(j\) 是区间内第 \(j\) 个潜变量步；\(q\) 是码本编号；\(c_k\) 是该区间的说话与倾听条件。注意 \(q\) 的连乘只是写法，实际上 18 个分量在给定隐状态后条件独立。

其他关键设置：

  • 上下文窗口 20 s。缓存刷新时保留最后 3 个块作为历史，保证动作连续。训练时生成器上下文同样封顶 20 s，用来限制缓存增长（附录 A.3）。
  • 生成器结构（附录 A.7）：从 Qwen2.5-0.5B-Instruct 初始化，24 层，隐藏维 896，14 个 query 头、2 个 KV 头，FFN 4,864；18 套独立 embedding 和输出头，每套词表 2,048。
  • 说话人风格：用一段 gesture prompt（发布代码里是 612 帧，约 20 s 的参考动作）提供风格。
  • RVQ 分词器（附录 A.1）：每个码本 2,048 项，码维 512，卷积宽 512；两级步长 2 的时间下采样；残差块深 6，膨胀增长率 3，ReLU；EMA 衰减 0.99，量化器 dropout 0.2。上半身输入是 13 个 SMPL-H 关节的 6D 旋转（78 维），双手 2×15 关节（180 维），面部接口 108 维（100 个表情系数 + 3 个头部姿态 + 1 个下颌张开 + 4 个眼球姿态）。头部朝向不由面部分词器管，而是由身体前向运动学给出。

发布代码里，18 路码本的 embedding 是这样加权求和的（摘自 code/modeling_ellsa2.py 的 _motion_ids_to_embeds，原文照录，仅省略开头的参数检查）：

def _motion_ids_to_embeds(self, motion_token_ids):
    """Sum weighted RVQ embeddings; negative IDs contribute zero."""
    motion_embeds = []
    for level in range(self.num_motion_codebooks):
        level_ids = motion_token_ids[:, :, level].clamp(min=0, max=self.motion_vocab_size - 1)
        invalid_mask = motion_token_ids[:, :, level] < 0
        level_embeds = self.motion_embeds[level](level_ids)
        # Mask on-device: testing .any() here would synchronize every codebook.
        level_embeds = level_embeds.masked_fill(invalid_mask.unsqueeze(-1), 0.0)
        motion_embeds.append(level_embeds * self.motion_embed_weights[level].to(level_embeds.dtype))
    return torch.stack(motion_embeds, dim=0).sum(dim=0)

3.2 嘴部子空间分解（§3.1 末段，附录 A.1，式 (1)）¶

面对面交流时口型最容易被看出问题，所以作者把嘴部运动从其他面部动态里单独拆出来建模。做法是：设 \(\boldsymbol{\psi}\in\mathbb{R}^{100}\) 为标准化后的 FLAME 表情系数，\(B\in\mathbb{R}^{100\times 8}\) 是一组正交的“嘴部基”，则

\[ \boldsymbol{\psi}_{\mathrm{mouth}} = B^{\top}\boldsymbol{\psi}, \qquad \boldsymbol{\psi}_{\mathrm{other}} = (I - BB^{\top})\,\boldsymbol{\psi} \]

嘴部基 \(B\) 由几何构造，而不是对测试表情做 PCA：取 SMPL-X 网格上支撑嘴部关键点的三角形所涉及的 51 个顶点，构造“表情系数 → 顶点位移”矩阵，按训练集表情标准差缩放各列，做 SVD 后取前 8 个右奇异向量，覆盖 99.6836% 的奇异值平方能量。这样 \(B\) 只依赖中性网格几何和训练集归一化，不碰评测数据。

分完之后：

  • 嘴部分支是 9 维（8 个嘴部坐标 + 下颌张开），用 2 个码本；
  • 非嘴部分支是 104 维（投影后的 100 维表情 + 4 个眼球维度），用 4 个码本；
  • 重建时先把预测出的非嘴部系数再投影回正交补空间，再与嘴部分量相加。

作者也提醒：正交性只在标准化系数空间成立，不代表两部分在解剖上影响的顶点互不重叠。

面部分词器的损失是（式 (2)）：

\[ L_{\rm VQ} = L_{\rm other} + 2L_{\rm mouth} + 4L_{\rm jaw} + 0.1L_{\rm lip} + 0.1L_{\rm vel} + 0.02L_{\rm commit} \]

前三项是标准化特征上的 MSE；\(L_{\rm lip}\) 是嘴部顶点误差（单位 mm²）。身体和手的分词器只用 MSE + \(0.02\times\) commitment。

拆分与合并的实现很短（摘自 code/models/vq/factorized_flame_model.py，原文照录）：

def split_features(self, motion):
    # motion: 标准化后的 FLAME 参数 (B, T, 108)
    expression = motion[..., :100]
    mouth_expression = expression @ self.mouth_basis                      # B^T ψ，8 维
    nonmouth_expression = expression - mouth_expression @ self.mouth_basis.T  # (I - B B^T) ψ
    nonmouth = torch.cat([nonmouth_expression, motion[..., 104:108]], dim=-1)  # + 4 维眼球 → 104 维
    mouth = torch.cat([mouth_expression, motion[..., 103:104]], dim=-1)        # + 下颌张开 → 9 维
    return nonmouth, mouth

def project_nonmouth_features(self, nonmouth):
    expression = nonmouth[..., :100]
    expression = expression - (expression @ self.mouth_basis) @ self.mouth_basis.T
    return torch.cat([expression, nonmouth[..., 100:104]], dim=-1)

def merge_features(self, nonmouth, mouth):
    nonmouth = self.project_nonmouth_features(nonmouth)   # 先投回正交补，防止两支打架
    expression = nonmouth[..., :100] + mouth[..., : self.mouth_rank] @ self.mouth_basis.T
    output = expression.new_zeros(*expression.shape[:-1], 108)
    output[..., :100] = expression
    output[..., 103:104] = mouth[..., self.mouth_rank : self.mouth_rank + 1]
    output[..., 104:108] = nonmouth[..., 100:104]
    return output   # 100:103 的头部旋转保持为 0，由身体姿态提供

（中文注释是我加的。）消融显示这种 4+2 分解比统一的 6 级 RVQ 好：说话帧 LVE 从 9.4962 mm 降到 8.8214 mm，MHD 从 2.0255 mm 降到 1.9031 mm（Table 13）。

3.3 接入全双工主干：隐状态条件化（§3.2，附录 A.3）¶

主干完全沿用 SALMONN-omni 的全双工时序框架：模型按固定时间块持续运行（主干步长 \(\delta=80\) ms），每步读入最新的输入语音表征，输出对应的文本 token；隐状态再驱动流式语音合成器和手势-表情生成器。主干是 thinker-talker 结构，文本先于语音生成，这一点在 3.4 节很关键。

两路条件分别取自：

条件流 来源 编码了什么
说话流 S 流式语音合成器处理输出语音 token 时的末层隐状态（25 Hz，相邻两帧拼接后降到 12.5 Hz） 模型自己要说的内容和声学实现
倾听流 L LLM 主干处理输入语音 embedding 时的末层隐状态（12.5 Hz） 当前声学上下文 + 推断出的对方对话状态

当主干输出 <silence> 时，语音合成器不工作，说话流条件换成一个可学习的空向量；倾听流始终开着。所以模型沉默时仍在持续生成手势和表情，可以做倾听反应。作者特别指出：轮次制（turn-based）模型通常只有被激活回答时才处理输入语音，做不到这一点，这正是全双工建模的价值。

为了不破坏预训练生成器已学到的声学通路，作者保留了原来冻结的 SPEAR 声学特征，把主干隐状态以残差的形式加上去（式 (4)）：

\[ c_k^{r} = \phi_k^{r} + \gamma_r(u)\,P_r\!\left(h_k^{r}\right), \qquad r\in\{\mathrm{L},\mathrm{S}\} \]
  • \(\phi_k^{r}\in\mathbb{R}^{10\times 896}\)：第 \(k\) 个区间冻结的声学条件，来自因果版 SPEAR 编码器（HF 权重，16 kHz、128 维 fbank 输入、1,280 维输出、最终 12.5 Hz）；
  • \(h_k^{r}\)：对齐后的主干或合成器隐状态；\(P_r\)：分组 + 投影到相同形状；
  • \(\gamma_r(u)\)：随训练步数 \(u\) 线性升温的残差系数，
\[ \gamma_r(u) = 0.01 + \min\!\left(\frac{u}{2500},\,1\right)\left(\gamma_r^{*}-0.01\right), \qquad \gamma_{\rm L}^{*}=0.1,\ \ \gamma_{\rm S}^{*}=0.25 \]

升温 2,500 步恰好等于第 3 阶段的训练步数（见 3.5 节）。说话流的最终权重比倾听流大一倍多。

完整系统的这部分代码没有开源。下面是我按式 (4) 写的示意，变量名是自拟的，仅用于理解：

# 示意代码（非官方）：式 (4) 的残差条件化
def residual_scale(u, gamma_star, warmup=2500):
    return 0.01 + min(u / warmup, 1.0) * (gamma_star - 0.01)

def build_condition(phi_k, h_k, proj, u, stream):
    """phi_k: (10, 896) 冻结 SPEAR 声学条件；h_k: 主干/合成器隐状态"""
    gamma = residual_scale(u, 0.1 if stream == "listen" else 0.25)
    return phi_k + gamma * proj(h_k)          # proj = 分组 + 线性投影 (+LayerNorm)

3.4 语义调用与模板引导（§3.3，附录 A.4–A.5）¶

问题：有明确含义的手势（比如张开双手表示“大”）在对话录像里很稀疏，而且需要高层语义理解。按常规方式训练，大量无语义的节拍动作会主导损失，模型就只学会跟着语音节奏晃手。

核心思路：把“要不要做一个语义手势”和“怎么做”拆开：

  1. 对话主干判断当前上下文是否需要语义手势；
  2. 一旦需要，就从模板库里检索一条高质量示范动作，用来引导生成器做出语义一致的动作。

具体流程：

  1. 词典路由（router）：词典把每个规范化的多词短语对应到一个动作族（action family）。在生成的文本中，路由器在每个短语结束处保留最长匹配，把候选挂在短语最后一个子词 token 上。这一步只说明“有一个可用的动作”。
  2. 调用头：在候选 token \(i\) 处，混合主干第 16、20、24 层的隐状态，经过 LayerNorm → Linear → SiLU → Dropout 0.1 → 标量 sigmoid，输出调用概率 \(p_i\)。它的输入是因果的回复前缀和之前已观察到的对话上下文。
  3. 判定：要求 \(p_i\ge\tau\) 且动作族唯一确定，再加 2-token 非极大值抑制。阈值 \(\tau=0.706\)，在平衡的开发集上按事件 F1 选定（0.001 网格搜索），测试时固定。
  4. 选模板：同一动作族内按语义置信度、动作质量、可见度排序，默认取第一名。
  5. 引导生成：把模板的 token（带分隔符）插在对应块的开头，位于语音条件和目标码之前。生成器学的是“在有引导时续写”，而不是把模板姿态直接贴上去。模板只引导上半身和双手的 12 路码本；面部和嘴部仍然跟随当前对话，避免把模板说话人的口型搬过来。模板 token 的标签设为 \(-100\)，不进损失。引导覆盖已核验的事件区间，按 133 ms 的潜变量网格量化，每个区间最多 6 个引导步；区间结束后恢复自由生成。

为什么不增加延迟：语义调用的决定必须在对应手势生成之前做出，否则检索和引导都会带来额外延迟。thinker-talker 架构天然满足这一点：文本生成跑在语音合成前面，调用头可以在“超前”的文本表征上预测，提前准备好模板，再和语音同步执行。模板按锚定短语结束词的时间戳排期，让语义手势和这个词对齐；超前的文本为模板的准备动作和计算留出了提前量。作者把这一点视为“手势生成接入全双工主干”的额外好处。

调用头的监督信号（附录 A.4）：作者刻意区分“原说话人实际做了某个手势”和“此处适合做某个手势”。监督用的是后者：

4.1 说话人级筛选：3,401 人里只留 81 人（附录 B.1）¶

训练数据只用 Seamless Interaction 的一个子集。作者的观察是：同一句话，有人大幅比划，有人轻微晃动，有人几乎不动，这些都是自然的；但几乎静止的说话人对学习区分说话和倾听没有帮助，还会把模型带向过度静止。所以要挑说话时手势清晰、说话和倾听状态差异明显的人。

做法是在 60 s 窗口（30 s 步长）上计算 6 个质量分量，加权得到窗口总分（式 (19)）：

\[ Q_w = 0.12S_w^{\rm valid} + 0.10S_w^{\rm smooth} + 0.10S_w^{\rm range} + 0.32S_w^{\rm energy} + 0.30S_w^{\rm compat} + 0.06S_w^{\rm vis} \]
  • \(S^{\rm energy}\)：按动作能量在全库中的分位数打分，偏好中等活跃度，压低静止和极端活跃的窗口；
  • \(S^{\rm compat}\)：按“说话占比”\(f_w\) 插值，说话为主的窗口偏好中等活跃，几乎不说话的窗口偏好低活跃。

能量定义为 \(E_w = 0.45E_w^{\mathcal B} + 0.55E_w^{\mathcal H}\)，其中

\[ E_w^{\mathcal G} = \frac{1}{(T-1)\lvert\mathcal G\rvert}\sum_{t=1}^{T-1}\sum_{j\in\mathcal G}\lVert\Delta\boldsymbol\theta_{t,j}\rVert_2 \]

窗口通过还需满足一组硬阈值。然后在说话人级别汇总（式 (23)）：

\[ \operatorname{keep}(s) = \mathbf 1\{N_s\ge 1,\ P_s\ge 0.70,\ \overline Q_s\ge 0.90,\ \overline C_s\ge 0.90,\ O_s\le 0.01\} \]

其中 \(P_s\) 是通过率，\(\overline Q_s\) 是平均质量，\(\overline C_s\) 是平均兼容分，\(O_s\) 是极端活跃窗口占比。结果：735,705 个窗口里 294,700 个通过；最终保留 81 名说话人、1,318 段录音。

5.2 手势：两个运动学指标 + 两个 MLLM 指标¶

说话-倾听活跃度比（式 (24)）：\(R_{\rm SL} = E_S / E_L\)。\(E_S\)、\(E_L\) 分别是说话帧和仅倾听帧上 13 个上半身关节的平均相邻帧位移。目标人说话（含重叠）算 S，目标人沉默且对方说话算 L，双方都沉默的帧剔除。

韵律对齐分 \(A\)（式 (25)）：对同一段手势，分别计算它和匹配语音、另一会话另一个人的不匹配语音的相关性，再比较二者：

\[ A = \frac{1}{N}\sum_{n=1}^{N}\sigma\!\left(\operatorname{clip}\!\left(\frac{c(a_n,g_n)-c(a_n^{-},g_n)}{s},\,-8,\,8\right)\right), \qquad s=0.207 \]

其中 \(c(a,g)\) 是音频起音强度与上身角速度能量（都插值到 20 Hz、做 0.25 s 高斯平滑、稳健标准化）在 \(\pm0.4\) s 延迟范围内的最大余弦相关。\(A=0.5\) 表示匹配和不匹配一样。这种对比式设计的好处是：一味乱动的动作拿不到高分，因为它和任何语音的相关性都差不多。

def standardize(values):
    values = np.nan_to_num(np.asarray(values, dtype=np.float64))
    median = np.median(values)
    scale = np.quantile(np.abs(values - median), 0.75) + 1e-06
    return np.clip((values - median) / scale, -8, 8)

def correlation(left, right):
    (left, right) = (standardize(left), standardize(right))
    denominator = np.sqrt(np.sum(left * left) * np.sum(right * right))
    return float(np.sum(left * right) / denominator) if denominator > 1e-08 else 0.0

def plausible_correlation(audio_cache, motion_times, motion_energy):
    cached = np.load(audio_cache)
    audio_times = np.asarray(cached['times'])
    duration = min(float(audio_times[-1]), float(motion_times[-1]))
    grid = np.arange(0, duration, 0.05)                      # 20 Hz 公共时间轴
    if len(grid) < 20:
        raise RuntimeError(f'Clip too short: {audio_cache}')
    onset = np.interp(grid, audio_times, cached['onset'])
    body = np.interp(grid, motion_times, motion_energy)
    onset = gaussian_filter1d(onset, 0.25 / 0.05)             # σ = 0.25 s
    body = gaussian_filter1d(body, 0.25 / 0.05)
    values = []
    for lag in range(-8, 9):                                  # ±8 帧 = ±0.4 s
        if lag < 0:
            values.append(correlation(onset[-lag:], body[:lag]))
        elif lag > 0:
            values.append(correlation(onset[:-lag], body[lag:]))
        else:
            values.append(correlation(onset, body))
    return float(np.max(values))

  • \(D_0\) 中：\(T\) 是时机，\(P\) 是对话适切性，\(V\) 是可见度；
  • \(S_0\) 中：\(V\) 是可见证据，\(M\) 是语义匹配，\(K\) 是具体程度，\(F\) 是节拍/小动作惩罚。

两者再对事件之外的行为打折：\(Q = Q_0(1-0.45U-0.35O)\)。\(U\) 惩罚目标人沉默时无理由的动作，\(O\) 惩罚其他时段的过度活跃。沉默区间来自低于 −40 dBFS 的 20 ms 音频窗，两端各裁 0.3 s，剩余至少 1 s 才保留。评委必须给出带时间戳的证据，同一区间不能被两种惩罚重复计算。

提示词里有一条“防幻觉规则”（附录 G.1），原文如下：

ANTI-HALLUCINATION RULE: transcript, VAD, category, audio, and VIDEO 1 identify what and
when to inspect, but they do not prove that VIDEO 2 performs a motion. Independently verify
the candidate's visible change. Do not copy the reference description into the candidate
description.

评分解析与合成（摘自 code/evaluation/activity.py 的 parse，原文照录，略去前半段的格式校验）：

if entry['task'] == 'duplex':
    base = 0.45 * d['Timing'] + 0.45 * d['Appropriateness'] + 0.10 * d['Gesture backchannel visibility']
else:
    base = float(np.clip(0.35 * d['Visual clarity'] + 0.45 * d['Text-motion semantic match']
                         + 0.20 * d['Concreteness'] - 0.30 * d['Beat/fidget penalty'], 0, 1))
return {'base': base, 'silence': S, 'overactivity': O,
        'deduction': base * (0.45 * S + 0.35 * O),

被略去的校验部分会检查：每个正的惩罚至少有一个具体区间；沉默证据必须 ≥1 s、target_speech_absent 为真，且落在低能量窗内；两类惩罚的区间不能重叠。这套校验相当严格，值得借鉴。

人工评测（附录 C.4）：2 名标注者，每人 966 条（7 个系统 × 138 条），以人类参考为 5 分锚点，给 1–5 分。评测界面隐藏系统名，见 Figure 5。

5.3 表情¶

表情指标沿用 UniLS 的实现（附录 C.5）：

\[ \mathrm{LVE} = \sqrt{\frac{1}{\lvert T\rvert}\sum_{t\in T}\max_{j\in J_{\rm lip}}\lVert\hat v_{tj}-v_{tj}\rVert_2^2}, \qquad \mathrm{JDD} = 100\left\lvert \operatorname{sd}_{t}(\hat\theta_{t,x}) - \operatorname{sd}_{t}(\theta_{t,x})\right\rvert \]
  • LVE：说话帧上的最大唇部顶点误差；
  • MHD：整个头部的顶点误差；
  • FDD：上半脸顶点时间标准差之差；
  • JDD：下颌张开角时间标准差之差。

FDD 和 JDD 分说话（S）和非说话（N）两种状态分别计算。比较时都固定头、颈、眼的姿态，只看表情和下颌。

七、存疑与不一致之处¶

  1. 轮次转换其实比 SALMONN-omni 略差，正文没有点明。 SALMONN-omni 的四项 TT 平均是 \((99.7+99.6+92.8+92.0)/4 = 96.0\%\)，ELLSA 2 是 95.2%。差距主要来自 AlpacaEval（87.9 vs 92.0）。正文用“保留了可靠的对话时机”带过，并没有说这是一次小幅退化。另外，TT 只衡量“提问结束后 2 s 内开口”，语音侧没有评测打断、附和等更难的全双工行为；这些只在手势侧的双工分里体现。

  2. 联合训练本身并没有提升语义手势，提升几乎全部来自模板。 不加引导时，ELLSA 2 的人工语义分（2.014）低于独立生成器（2.070），和仅说话的 MIBURI（2.014）持平。MLLM 双工分的第一名也是独立生成器（0.318），而不是 ELLSA 2（0.300）。所以“联合优化提升手势质量”这个结论主要建立在人工双工分（3.007 → 3.201）和 \(A\) 上。

  3. 语义测试集与模板库存在有利于本方法的选择偏差。 附录 B.4 写明，71 条语义片段是按“现有模板库能支持”筛选的。另外，模板库的源池是 121,054 段录音，和消融里“全量训练池”的数字完全一样，而测试集取自 Seamless 的测试划分。论文没有明确说明模板库是否排除了测试会话，因此无法判断是否可能存在泄漏。

  4. 调用头的 87.8 F1 不是端到端检测指标。 它衡量的是：在词典已经匹配到短语的位置（候选条件化），并且在正负平衡的测试集上，判断“这个可用动作是否合适”。召回上限受 2,072 个短语的词典限制，标签也来自 GPT 和 Seed 两个 LLM，而不是人工标注。

  5. \(R_{\rm SL}\) 标为“越高越好”值得商榷。 它只是说话与倾听活跃度之比，并不是越大越自然；论文也没有报告人类参考动作的 \(R_{\rm SL}\) 是多少。附录 C.2 自己也说它“只衡量相对活跃度”。

  6. 相关性分析的样本量很小。 系统级相关只有 \(n=7\)；GENEA 上 \(A\) 的验证也只有 7 个系统，附录承认这些只是描述性统计。样本级相关只有 0.40–0.56，说明单条片段上 MLLM 评委并不可靠。

  7. 发布配置与论文超参不完全一致。 Table 5 写的 S2（手势）阶段是学习率 \(4\times10^{-5}\)、50k 步、全局 batch 256。但发布的 training.json 里 gesture 阶段是学习率 \(10^{-4}\)、max_steps: 10000，每卡 batch 8 × 梯度累积 2（按 README 的 8 卡计算，全局 batch 是 128）。可能是开源版换了配方，但仓库没有说明。

  8. 代码里有论文没提到的模块。 modeling_ellsa2.py 中有 ListenerLowRankDelta、ListenerCausalConvGate 和一个基于 motion_backchannel_mask 的“倾听门控”损失（带正样本权重和死区损失），正文和附录都没有描述。它可能是专门针对附和类倾听反应的结构，但论文没有交代，影响可复现性的判断。

  9. 状态定义前后不统一（论文自己有说明）。 表情指标的“非说话”包含双方都沉默的帧，而 \(R_{\rm SL}\) 的“倾听”排除了这种帧。Table 4 的图注写 S/N，附录 E 又写成 S/L，读表时容易混淆。

  10. 完整模型未开源。 目前只能复现独立生成器。主干、合成器、语义调用头和 10.78B 的完整权重都要等“录用后”。

八、与对话交互研究的关系¶

1. “语义调用”本质上是一种工具调用，而且给出了一个低延迟的范式。 把它和全双工模型中的工具调用对照，结构几乎一一对应：

ELLSA 2 的语义调用 全双工工具调用
词典匹配：确认有一个可用动作 确认有一个可用工具（候选生成）
调用头读主干中间层（第 16/20/24 层），sigmoid 判断“是否适合” 一个轻量的判定头决定是否调用（不占主干的自回归步）
从模板库检索示范动作 执行工具，取回结果
模板 token 插进下游生成器的序列，而不是主干的序列 工具结果注入负责执行的子模块，而不是塞进主干上下文
利用 thinker 领先 talker 的时间差，提前准备模板 利用文本领先语音的时间差，异步执行工具、掩盖延迟

其中“whether 和 how 解耦”以及“利用超前文本获得提前量”两点，可以直接借用到异步工具调用的设计里。软标签的构造方式（两个 LLM 独立打分，只保留分歧不超过 1 的样本）也可以用来标注“此处是否应该调用工具”这类没有标准答案的策略数据。

2. 对“上下文爆炸”问题，它给出了第三种做法：把新模态放进独立的子模型，并单独封顶。 Moshi-Face 的做法是在每个时间步多加几路并行流，增加的是“宽度”，时间轴长度不变。ELLSA 2 则把手势和表情放进一个 0.5B 的独立生成器，它有自己的 20 s 上下文（刷新时保留 3 个块），主干的对话上下文（4,800 token）一个手势 token 都不用承担。主干只通过隐状态向生成器单向供给条件。这种“主干 + 带独立短窗口的从属生成器”的结构，可以推广到任何高频、低语义密度的输出流（动作、表情、机器人电机指令等）。代价是生成器只能看到 20 s 的历史，长程的风格一致性要靠风格 prompt 来维持。

3. 倾听行为必须依赖全双工。 论文最有说服力的论点是：模型沉默时，说话流换成空向量，倾听流继续驱动点头和表情。轮次制模型在不回答时根本不处理输入，自然做不到这一点。这为“为什么要做全双工”提供了一个语音之外的理由。

4. 对数字人和机器人脸的直接价值。

  • 已开源的独立生成器可以单独用：它只需要双方音频和一段风格参考，输出 SMPL-H 身体 + FLAME 表情，每 0.8 s 一块。可以接在任何全双工语音模型后面做级联，作为 Audio2Face-3D 之外的另一个 avatar 驱动层（A2F 只管脸，而且只看说话人自己的音频）。
  • 0.8 s 一块意味着动作延迟至少有一个块长，比 A2F 那种帧级流式要粗。
  • 嘴部 8 维子空间 + 下颌单独编码这一做法，对机器人口型很有参考价值（参见 Lip）：它从几何上保证口型通道不被其他表情挤占，消融显示 LVE 下降了 0.67 mm。
  • 说话人筛选的结论（81 人好于 3,401 人）提醒我们：做数字人或机器人的动作数据时，“动作是否清晰、听说差异是否明显”比数据量更重要。

5. 评测上可以直接借用的东西。

  • 匹配/不匹配对比式的韵律分 \(A\)：能防止“乱动刷分”，代码已开源；
  • 带人类参考的 MLLM 评委，加上严格的 JSON 校验（每个惩罚都要给时间戳证据，区间不能重复计算），适合做全双工行为的批量回归测试；
  • 138 条按附和、重叠、双向打断分类的测试集，可以直接拿来评测我们自己的 avatar 层。

6. 局限：只有英文的 Seamless Interaction 数据；没有视觉输入（论文自己承认）；模板库只来自单一数据源；完整模型未开源。目前更适合把它当作“架构与评测方法的参考”，可以直接拿来用的只有独立生成器和评测工具。
